# D2Sync

## Qué es
App de escritorio Windows para gestionar cuentas de Steam en el mismo PC: sincroniza la configuración de Dota 2 (carpeta `570`) entre cuentas, guarda/restaura backups manuales, elimina cuentas locales (con opción de quitarlas del launcher de Steam) y activa/desactiva Steam Cloud para Dota 2. Interfaz bilingüe español/inglés.

Migrado el 23/08/2026 de Flutter + lanzador C# casero a **Avalonia (C#)**, la herramienta única de escritorio del stack unificado.

## Cómo se ve y funciona
Ventana sin marco nativo (franja superior arrastrable, minimizar/cerrar). Pantalla **Home**: título "D2Sync" / "by Nexo", toggle de idioma ES/EN arriba a la derecha, grilla de 5 botones (Sync data, Backup, Delete Acc, Cloud, Optimized — quedan siempre en inglés a propósito, son la marca de cada función). Cada botón abre una sección con header compartido (← Regresar, ícono+título+resumen, botón "Cómo funciona" que abre un popup con pasos numerados) y su propio contenido. Todas las pantallas comparten la misma barra inferior: botón "Actualizar cuentas" (con cooldown de 5s), cantidad de cuentas encontradas, versión + aviso de actualización pendiente si la hay. El usuario elige cuenta(s) de Steam detectadas automáticamente desde el registro (`HKCU\Software\Valve\Steam`); toda operación destructiva pide confirmación y las de sync/carga de backup guardan un respaldo temporal que se restaura si algo falla.

## Stack
- **Avalonia 11 (C#, .NET 8) + CommunityToolkit.Mvvm** — misma base que Botrix Refill (source generators, `net8.0-windows` por la sintaxis de "partial properties" de C# 13 que el SDK instalado no soporta).
- **`Microsoft.Win32` / `System.Diagnostics.Process`** — lectura del registro de Windows (`reg.exe`) y detección de procesos abiertos (`Process.GetProcessesByName`, reemplaza el `tasklist.exe` original).
- **Velopack** — auto-actualización vía GitHub Releases, reemplazo atómico del exe (reemplaza el lanzador C# casero + repo de updates propio que tenía la versión Flutter).

## Archivos clave
- `Services/SteamSyncService.cs` — misma lógica exacta que la versión Dart, incluyendo el bug real ya corregido ahí: `localconfig.vdf`/`sharedconfig.vdf` son archivos grandes donde el appid `570` puede aparecer en secciones no relacionadas — `ExtraerBloqueApp()` primero ubica la sección `apps` y recién ahí busca el appid dentro. También conserva: validación de que toda ruta de escritura esté dentro de `userdata` antes de tocar nada, restauro automático si una copia falla a medio camino, y la reescritura de Launch Options que solo toca las flags que este programa gestiona (conserva cualquier texto que el usuario haya puesto a mano).
- `ViewModels/SectionViewModelBase.cs` — cada sección se suscribe a `LanguageService.Changed` y llama `OnPropertyChanged(string.Empty)` para refrescar todo su texto bilingüe de una vez al cambiar de idioma, sin tener que enumerar cada propiedad individualmente.
- `Services/Strings.cs` — puerto directo de la clase `S` de Dart; cada getter/método lee `LanguageService.IsEnglish` en el momento de evaluarse.
- `Views/SectionHeaderView.axaml` / `Views/BottomBarView.axaml` — extraídas como controles reutilizables (en la versión Dart cada pantalla repetía este chrome) para no duplicar la lógica 5 veces.

## Instalar y correr
```bash
cd project/D2Sync
dotnet restore     # primera vez
dotnet run          # desarrollo
dotnet build        # solo compilar
```
**Publicar una release nueva:** crear tag `vX.Y.Z` y pushearlo — `.github/workflows/release.yml` compila, empaqueta con `vpk` y publica el GitHub Release solo. También se puede disparar manual (`workflow_dispatch`) indicando la versión.

**Distribución al usuario final:** se comparte el link del Release (`github.com/AndreDiaz11/d2sync/releases`), nunca una copia del `.exe` guardada en el proyecto. El usuario descarga el `.zip` portable (sin instalador) y corre el `.exe` de adentro.

## Env vars
No requiere ninguna. Config de usuario (idioma, última versión vista) en: `C:\Users\{usuario}\AppData\Roaming\d2sync-app\config.json` — carpeta propia, distinta a la de la versión Flutter, para que cada instalación nueva arranque limpia.

## Auto-actualización
Vía GitHub Releases (Velopack), repo: `AndreDiaz11/d2sync`. Revisa al abrir (en paralelo con el chequeo de Novedades, no uno detrás del otro), popup "Ahora no"/"Actualizar", reemplazo atómico del exe.

## Novedades para el usuario
Sí — popup tipo WhatsApp una sola vez por versión nueva (mismo patrón que Botrix Refill).

## Despliegue
Repo **público** (excepción justificada, mismo criterio que Botrix Refill y RS Quest Compass Plugin: necesita leer GitHub Releases sin token embebido en el cliente; sin secretos en el repo).

**Usuarios de la versión Flutter vieja (repo `d2sync-updates`, separado):** ese repo queda tal cual, sin publicar nada más ahí — sus usuarios se quedan en la última versión Flutter (1.2.9, funcional). El mecanismo de auto-update de esa versión vieja solo muestra un número de versión, sin texto personalizado, así que no hay forma de mostrarles un aviso de "descarga la nueva versión" sin recompilar la app Flutter (decisión tomada con el usuario: no vale la pena ese esfuerzo). El link de la nueva versión se comparte manualmente.
